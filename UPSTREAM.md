# Upstream maintenance

Direct upstream: https://github.com/Equicord/Equicord (main). Original upstream: https://github.com/Vendicated/Vencord. main remains a clean mirror; dev carries Alliance changes; prod receives tested promotions. Set dev as the default branch so scheduled workflows exist without contaminating main.

sync-upstream.yml runs at minute 17 every six hours and supports manual dispatch. Schedules may be delayed by GitHub. It fetches full history, fast-forwards main and refuses divergence without force-pushing. Failures are visible in Actions. Successful runs start sync-development.yml through workflow_run, even when GITHUB_TOKEN pushes do not trigger workflows.

Development integration uses one allicord/upstream-sync branch and one open PR. A changed main/dev pair is merged and validated in a read-only job. A separate publisher job only pushes the validated commit, rechecks both branch heads and creates or updates the PR. Conflict issues are reused and closed after successful validation. No write token is exposed to merged build code. PRs created by GITHUB_TOKEN may not trigger ordinary PR CI, so integration validation runs within the sync workflow. Required checks may need a maintainer-triggered build run on the integration ref before merging.

Enable Actions, issues and Allow GitHub Actions to create and approve pull requests. main must permit fast-forward pushes by the sync workflow; protect it against force pushes and deletion. Protect dev/prod with required reviews and the Validate check, allowing history-preserving merges for upstream PRs. Protect v* release tags against update/deletion and configure a release environment with required reviewers. Disable inherited publish.yml and nixosBuild.yml repository workflows before switching on synchronization: the untouched mirror still contains upstream release workflows. Keep main-only build/test workflows disabled as needed to avoid upstream automation. No PAT or GitHub App secret is required for the implemented integration.

If main diverges, inspect the ancestry and preserve accidental commits on a separate branch. Do not reset or force-push. Reconcile with a maintainer before retrying. For development conflicts, reproduce a merge of main into dev on a temporary branch, resolve only overlapping changes, run validation and merge the integration PR. On publication failure, re-run development synchronization; it reuses the branch and PR. Never bypass validation to promote prod.
